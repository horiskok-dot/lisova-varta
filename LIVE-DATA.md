# Подключённые источники

## Open-Meteo

Модель погоды для центра карты, влажность, ветер и прогноз на три дня. Отображаются координаты и время модели; расчёт не выдаётся за измерение на месте. Поиск населённых пунктов — Open-Meteo Geocoding. Ключ для некоммерческого открытого API не нужен. [Документация](https://open-meteo.com/en/docs).

## OpenStreetMap

Небольшой участок приблизительно 3 × 3 км вокруг центра карты загружается через read-only API v0.6. Водоёмы, гидранты, резервуары и точки забора отображаются отдельным слоем. Добавление объекта в журнал — явное действие пользователя. Импорт не помечает объект как проверенный. Координаты полигона — приблизительный центр, не гарантированное место забора воды. Покрытие зависит от наполнения OSM. [Документация](https://wiki.openstreetmap.org/wiki/API_v0.6).

## NASA FIRMS

Публичная европейская CSV-выгрузка VIIRS S-NPP за 24 часа. Сервер фильтрует её по видимой области карты. Показаны источник, время загрузки и наблюдений. Один спутник не даёт полного покрытия; термоаномалия не равна подтверждённому лесному пожару. Ноль отметок не означает отсутствие пожаров. Другие спутники и регионы пока не подключены. Ключ для этой публичной выгрузки не требуется. [Выгрузки](https://firms.modaps.eosdis.nasa.gov/active_fire/).

## Сервер и ограничения

Сервер принимает только фиксированные источники, не работает как произвольный URL-прокси. Координаты и размер области валидируются. Кэш в памяти экземпляра Worker: погода/FIRMS — 15 минут, OSM — 24 часа. Таймауты, HTTP-ошибки, отсутствие данных и неполный ответ показаны пользователю. Публичные API не имеют SLA. Для большого числа пользователей нужны устойчивый источник геоданных и распределённый кэш.

Погода и поиск населённых пунктов обращаются напрямую из браузера к открытым CORS API Open-Meteo; серверные обработчики остаются резервными. Это исключает зависимость только от квоты общего серверного IP, на котором наблюдался HTTP 429. Прямое обращение передаёт поставщику выбранные координаты/название и обычный сетевой IP, но не ключи или учётные данные сайта. В пустом новом журнале водные объекты загружаются один раз для первого участка; далее — по кнопке. NASA — по кнопке. Фонового опроса нет. Полевой режим отменяет выполняющиеся запросы и отключает подложку и обновления. Ошибки одного источника не накапливаются и не удаляют его последнюю сохранённую копию. API и страницы входа не заменяют автономный кэш приложения.

## Обновление старого журнала

Исходные неизменённые учебные записи 0.1 убираются из активного журнала. Старый журнал целиком сохраняется в localStorage как резервная копия; кнопка скачивания находится в «Как это работает». Изменённые пользователем записи сохраняются с предупреждением. Общей базы и синхронизации сотрудников нет: журнал по-прежнему хранится на устройстве.
